# Surface brief — Radar de Benefícios V12 / Console de sintonia

Mode: operate. Scope: one new Android compact visual prototype and its design
documentation. Preserve the existing Flutter route map, API-backed data,
authorization, pagination, query state, external links and honest data states.

## Direction contract

THESIS: Make the product read as a working set of monitored channels. The user
should understand source, data quality and next action before reading a grid of
promotional cards.

OWN-WORLD: Matte graphite and cool paper, saffron brand signal, ice-blue Inter,
leaf-green availability and red fault marks. Orthogonal frames, editorial rows,
one controlled channel grammar, no rounded card stack, no glow, no literal radar
circles.

STORY: Arrive at the API snapshot, inspect each domain, enter Livelo or Inter or
Pichau, search and paginate real records, follow a store/product, inspect a
benefit or history, recover honestly from a failed/empty/stale state, and return
without losing useful context.

FIRST VIEWPORT: A quiet context index and a single summary strip lead into
full-width channel rows for Livelo, Banco Inter, Produtos Inter and Pichau. The
bottom rail exposes only Resumo and Serviços; Conta stays contextual.

FORM: Console de sintonia. The active channel is continuous, delayed is
interrupted, failed is crossed, missing is open-ended. The line is a semantic
accelerator, never the only state signal and never a repeated decoration.

FINISH: unreviewed and undocumented is unfinished; this prototype ends with a
critical anti-slop pass, a real redesign round, documented tokens, and a clear
stop before Flutter implementation.
